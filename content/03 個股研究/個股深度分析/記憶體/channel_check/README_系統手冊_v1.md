# 供應鏈情報系統・系統手冊 v1（記憶體鏈）

**2026-08-09 上線・祖曜筬 × Claude・架構預留多族群**

## 一、定位

從 monitor_optical v3（光通訊）升級而來：從「監控告警器」升級為「情報消化系統」。
每一筆進來的資訊，必須落到**三張嘴**之一，落不到＝噪音、丟棄：

1. **模型參數**——營收橋的具體格子（PRICE_DRAM/NAND 路徑、位元 proxy、HBM 份額、傳導率）
2. **快槍賭注對帳**——有對帳日的賭注，到期自動備好判定素材
3. **背離解讀**——印反應溫度計＋慢燉/事件卡的觸發偵測

## 二、架構（與 v3 的根本差異）

**雲端 runbook 制**：排程任務＝一份完整的作業指令（fresh session 自帶全部脈絡），抓取一律走 **WebFetch**。
2026-08-09 實測結論（本架構的依據）：雲端容器 python 直連被 proxy 全擋（requests 全滅）；
MOPS 連 WebFetch 都 404；**statementdog ✓、TrendForce ✓、公司 IR 官網 ✓** 可達。
所以：⚠ 任何 runbook 不得用 bash/python 直連網站；台鏈月營收主源＝statementdog、備源＝財經新聞。

## 五、紀律（v1→v3 用故障換來的，全數沿用）

1. 只收一手或準一手：官方申報、交易所、公司 IR、產業研究機構；轉載源標明轉載
2. 差分才告警——沒變化只進 digest，避免警報疲勞
3. 失敗要出聲：抓不到就寫「無資料／需人工查」，**不硬湊**
4. 已知長期不可達的來源（MOPS、FS.com 類）列「需人工查」，不佔紅色警報
5. 產出全部 append 存檔（矩陣／週掃描／intel_log）——檔案本身就是日後的校準資料集

## 六、情報卡（見 情報卡_模板.md）

公開資訊與人脈訊息用同一張卡。核心欄位：來源層級（官方／官方匿名／外媒／傳聞／**一手人脈**）、
可交叉驗證點、半衰期、**映射（哪個參數或賭注）**、**合法性自檢**（重大性×非公開性——馬賽克拼圖合法、MNPI 不碰）。
全部 append 進 intel_log.md。
